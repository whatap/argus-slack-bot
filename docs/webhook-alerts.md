# 전용 채널의 WhaTap 알림 (선택 기능)

기본값은 꺼짐이다. 사용자 WhaTap OAuth 모드에서 아래 **세 값이 모두** 유효해야 수신한다. 값은 전용 앱의 런타임에만 설정한다. 실제 ID·알림 원문·웹훅 URL·토큰을 이 저장소에 넣지 않는다.

| 변수 | 값 |
|---|---|
| `SLACK_ALERT_TEAM_ID` | Slack 워크스페이스 ID 하나 |
| `SLACK_ALERT_CHANNEL_ID` | 수신 채널 ID 하나 (이름이 아님) |
| `SLACK_ALERT_BOT_IDS` | 수신을 허용할 발신 웹훅의 `bot_id`. 복수이면 쉼표 구분. `app_id`나 봇 사용자 ID가 아님 |
| `ALERT_TIME_ZONE` | (선택) Webhook JSON 알림의 epoch 시각을 적을 IANA 시간대 이름(예: `Asia/Seoul`). 없으면 Webhook JSON 알림은 읽지 않는다(기존 동작). 틀린 이름이나 `+09:00` 같은 오프셋이면 봇이 시작하지 않는다 |

운영 HTTP 매니페스트·설치 scope는 바꾸지 않는다. 별도 전용 앱이 해당 채널의 멤버이고, 비공개 채널이면 bot event `message.groups` + `groups:history`, 공개 채널이면 `message.channels` + `channels:history`를 받아야 한다. `chat:write`와 interactivity도 필요하다. user event나 Slack Connect는 이 기능의 수신 경로가 아니다. 환경변수만으로 Slack 구독이 추가되지는 않는다.

## 지원 범위와 동작

- 로컬 notihub의 `SlackDeliverer.createEntity` → `WebhookJSONBuilder.buildSlackMessage`는 단일 attachment의 `pretext`에 제목, `text`에 본문을 싣는다. 기본 제목(`locale/messages_ko.properties`의 `metric_common_subject`)과 `templates-v2/ko/{sm,not-sm}.not-email.vm` 중 대상 이름이 있는 형태를 읽는다. **대상 환경 배포본의 실제 템플릿과 Slack Events 봉투는 확인 전이다.** 스마트 알림, 사용자 템플릿, 다른 언어, 대상이 본문 서술에만 있는 형태는 추측하지 않는다.
- 허용된 봇의 원본 채널 메시지에만 `[분석]`을 스레드 답글로 붙인다. 수신·복구 자체는 Argus를 부르지 않는다. 버튼은 저장한 원본 및 봇 답글에 묶인다.
- `[분석]`을 누르면 누른 사람이 그 스레드에서 질문한 것으로 처리한다(멘션 질문과 같은 흐름). 그 사람의 OAuth로만 묻고, 답은 알림 스레드에 남는다. 로그인 링크만 본인에게 보인다. 공용 계정 대체 경로는 없다.
- 질문은 받아들인 알림의 칸(규칙 제목, 등급, 대상, 이벤트 메시지, 시작 시각)으로 만든 **SRE 사건 글**이다. argus-agents `sms.sre.incident`(`tools.py`가 계약의 정본)이 코드로 읽는 모양이고, 프로젝트는 알림의 프로젝트 코드를 그대로 넘긴다. 버튼 값, 수신자 목록, 바로가기 URL은 넘기지 않는다. 대상 이름에 `—`·`«»`·`(oid …)`가 있으면 줄 문법이 깨지므로 그 알림은 받지 않는다.
- 답에 OPM 조치안이 오면 기존 `[조치 실행]`·`[취소]` 버튼을 그 답 아래에 붙인다. 버튼은 `[분석]`을 누른 사람만 누를 수 있고, 실행 결과도 알림 스레드에 남는다. 봇은 조치를 스스로 실행하지 않는다(아래 «자동 대응»을 켜지 않았을 때).
- **OPM 조치안에는 서버 oid가 필요하다.** 사건 글의 대상 줄에 oid가 없으면(`oid 0`) Argus는 권고 명령만 내고 버튼은 내지 않는다. 알림 템플릿에는 oid가 없다. 이벤트 메시지에 `oid <숫자>`가 있으면 그 값을 대상 줄에 싣는다(규칙의 메시지에 oid 변수를 넣는 방법이며, 대상 환경에서 그 변수가 채워지는지는 확인 전이다). 서로 다른 값이 둘 이상이면 싣지 않는다. Webhook JSON 알림은 `서버 oid` 칸을 싣는다. Argus는 그 oid가 같은 이름의 OPM 관리 서버인지 확인한 뒤에만 버튼을 낸다. 이벤트 메시지에서 읽은 oid는 분석 질문에만 쓰고, 사람 없이 실행할 대상으로는 쓰지 않는다(아래 «자동 대응»).
- `NotiContextFactory.createLink`가 생성하는 `/link/event?pcode=…&archiveId=…`가 있으면 동일 출처·프로젝트·아카이브로 `RECOVERED: `를 연결한다. 링크는 발신 서버 설정(`use_event_route_link`, 기본 꺼짐)이 켜져 있을 때만 붙으므로, 링크가 없으면 발신 봇·플랫폼·프로젝트·대상·규칙 제목/조건·**이벤트 시작 시각**이 모두 같은 것을 같은 사건으로 본다. 링크 자체를 열지 않는다. 같은 Slack 메시지 재전달은 무시하고, 다른 시작 원본 둘이 같은 사건을 주장하거나 복구가 먼저 오면 그 사건은 연결하지 않는다(버튼도 거둔다).
- Webhook JSON 의 `status=cancel`(제목 `DISABLED: <규칙>`)은 규칙이 바뀌거나 꺼져 사건이 닫힌 것이다. 소요 시간 없이 `DISABLED:` 로 닫고 해소(RECOVERED)로 보지 않는다.
- `EventDateTimeHelper.eventTime()` 형식의 시간대 포함 시각으로 종료와 소요 시간을 적는다. 복구 제목과 사건 식별은 확실하지만 종료 시각이 생략된 경우에만 **Slack 수신 기준** 종료 시각 및 두 메시지의 수신 간격을 적는다. 잘못된 시각은 이 대체 경로로 넘기지 않는다.
- 단일 프로세스 메모리에서 최대 24시간, 2,048건을 추적한다. 포화되면 기존 항목을 밀어내지 않고 신규 수신을 제한하고, 만료된 항목이 빠져 자리가 나면 바로 다시 받는다(그사이 알림이 계속 와도 제한이 늘어나지 않는다). 제한 중에 거절한 사건은 24시간 동안 그 사건의 다시 보낸 시작 글·해소 글도 받지 않는다. 재시작·앱 삭제·만료로 상태가 없어지면 예전 버튼과 복구를 연결하지 않는다. 다중 인스턴스 간 중복 방지나 Slack 전송 실패 시 재시도/전달 보장은 없다.

실물 확인 시에는 원문이나 식별자를 복사하지 말고 일반/복구 각각의 봉투 필드, 제목 구조, 실제 대상·규칙·동일 아카이브와 시작 시각 유무를 먼저 대조한다. 다르면 미지원으로 둔 채 비식별 fixture와 해당 파서 테스트부터 추가한다.

## 자동 대응(온콜) — 선택 기능

기본값은 꺼짐이고, 꺼 두면 위 동작과 똑같다. 켜면 알림 채널의 **당번** 한 사람의 와탭 권한으로 새 알림을 바로 분석하고, 허용한 범위의 OPM 조치안 하나를 사람 확인 없이 실행한다.

| 변수 | 값 |
|---|---|
| `ONCALL_AUTO` | `1`이면 켠다(`0`·없음 = 끔). 와탭 로그인(OAuth) 모드와 `SLACK_ALERT_CHANNEL_ID`가 있어야 하고, 없거나 값이 틀리면 봇이 시작하지 않는다 |
| `ONCALL_AUTO_RULES` | 자동 대응할 규칙 이름(없으면 제목)에 들어 있는 낱말. 쉼표 구분, 대소문자 구분. 비면 어떤 알림도 자동 대응하지 않는다 |
| `ONCALL_AUTO_RISKS` | 자동 실행할 조치안 위험도(`normal`·`warning`·`critical`). 기본 `normal,warning` |
| `ONCALL_ESCALATE_MIN` | 자동 조치 뒤 이 분 안에 해소되지 않으면 당번을 부른다. 기본 10 (1~1440) |
| `ONCALL_KEEPALIVE_MIN` | 당번 토큰을 이 분마다 한 번 써서 이어 둔다. 기본 60 (1~479, 갱신 토큰 수명 8시간보다 짧게) |

명령은 알림 채널에서 봇을 멘션하고 멘션 뒤 글 전체가 아래 중 하나일 때만 받는다. Argus 에 묻지 않는다. 다른 채널·DM 에서 보내면 켜거나 끄지 않고 보낸 사람에게만 안내한다.

- `자동 대응 켜기` — 보낸 사람이 당번이 된다. 지금 쓸 수 있는 와탭 로그인이 있어야 하고, 없으면 로그인 링크만 본인에게 보내고 켜지 않는다. 당번은 와탭 연결과 같은 DB 파일(`oncall_owners`, 토큰 없음)에 남아 재시작 뒤에도 유지되고, 앱을 지우면 지운다.
- `자동 대응 끄기` — 멈춤 스위치. 채널의 누구나 끌 수 있다. 진행 중인 것도 멈춘다: 분석 중이던 사건은 끝나도 자동 조치를 하지 않고(조치안은 앞 당번만 누를 수 있는 버튼으로 남긴다), 걸려 있던 에스컬레이션도 부르지 않는다. 다른 사람의 `자동 대응 켜기`로 당번이 바뀐 경우도 앞 당번의 사건은 같다.
- `자동 대응 상태` — 당번과 설정을 보여 준다.

동작과 안전 한도:

- 당번이 있고 규칙이 대상인 새 알림만 `[분석]` 버튼 대신 당번 권한으로 바로 분석한다. 원본 글마다 한 번이고(재전송·같은 사건의 다른 시작 글은 다시 하지 않는다), 해소·닫힘 알림은 분석하지 않는다. 분석하는 사이 해소·닫힘 알림이 오면 자동 조치를 하지 않고 에스컬레이션도 걸지 않는다(조치안은 당번만 누를 수 있는 버튼으로 남긴다).
- 당번 로그인을 쓸 수 없거나 분석이 실패하면 스레드에서 당번을 부르고 `[분석]` 버튼을 그대로 붙인다. 로그인 링크는 당번에게만 보낸다. 부르는 글이나 링크를 보내지 못해도(예: 당번이 채널에 없음) 실패를 기록하고 `[분석]` 버튼은 붙인다.
- 자동 실행은 사건마다 **하나**다: 카탈로그 조치(`operant_action`)나 Argus 가 정한 스크립트 실행(`operant_execute`)이면서, 위험도가 `ONCALL_AUTO_RISKS` 안이고 알림의 서버(oid·프로젝트)를 겨냥한 첫 조치안. 위험도를 모르는 조치안과 스크립트는 `critical`로 본다. 같은 확인 토큰은 다시 자동 실행하지 않는다. 나머지 조치안은 당번만 누를 수 있는 버튼으로 남기고 당번을 부른다.
  - Job 등록·삭제(`operant_jobs_*`), 배포 시작·중지(`operant_deploy_*`), 범용 OPM API 호출(`operant_api_request`), 모르는 도구는 위험도 표시와 상관없이 자동 실행하지 않는다. 실제 대상이 인자(에이전트 목록·경로·본문)에 있어 봇이 무엇을 건드리는지 확인할 수 없다.
  - 조치안에 보이는 대상만이 아니라 OPM 에 가는 인자(`arguments`)도 확인한다. 인자의 `pcode`·`oid`가 알림의 서버와 같아야 하고, 서버를 가리키는 다른 칸(`oids`·`agentOid`·`agents`·`targets` 등, 안쪽 칸 포함)이 그 서버 말고 다른 것을 가리키거나 oid 없이 대상을 적으면 자동 실행하지 않는다.
  - 알림의 서버는 Webhook JSON 알림의 `서버 oid` 칸으로만 정한다. 템플릿 알림의 oid 는 이벤트 메시지(규칙을 만든 사람이 쓰는 자유 글)에서 읽은 값이라 분석에는 싣지만 자동 실행에는 쓰지 않는다. 그래서 템플릿 알림은 자동 분석까지만 하고 조치안은 버튼으로 남긴다. 알림에 oid 가 없어도 자동 실행하지 않는다.
  - 실행 직전에 채널이 아직 같은 당번으로 켜져 있는지 다시 본다. 아니면 실행하지 않는다(위 `자동 대응 끄기`).
- 실행 전에 무엇을 어디서 어떤 위험도로 실행하는지 남기고, 결과도 스레드에 남긴다. 실패(2xx 아님·응답 없음·로그인 만료·쓰기 허락 없음)이거나 결과가 «실행함»이 아니면(결재 대기·실패 등) 바로 당번을 부른다.
- 실행된 뒤 `ONCALL_ESCALATE_MIN`분 안에 해소되지 않으면 스레드에서 당번을 한 번 부른다. 해소되면 해소 글에 «자동 조치 후 N분 만에 해소 (봇 기준)»을 덧붙인다.
- 토큰 유지: 켜져 있는 동안 `ONCALL_KEEPALIVE_MIN`분마다 당번 토큰을 한 번 쓴다(만료됐으면 이때 갱신된다). 갱신이 거절되면 알림 채널에 한 번만 알리고 로그인 링크를 당번에게만 보낸다. 당번은 지우지 않으며 다시 로그인하면 조용히 이어 간다.
- 단계마다 `[argus-slack-bot] oncall at=… team=… channel=… root=… owner=… step=…` 한 줄을 남긴다(토큰·본문 없음). 사건 상태와 에스컬레이션 타이머는 프로세스 메모리에만 있어 재시작하면 사라진다.
